# anion-tv — план реализации

Нативное приложение для Android TV: каталог аниме + просмотр на телевизоре.
Личное, ставится sideload'ом, в Google Play не пойдёт.

Соседние репозитории: [anion](../anion) (веб, Angular 22 SSR), [anion-go](../anion-go)
(бэкенд, Gin, проксирует `api.yani.tv`), [anion-dl](../anion-dl) (десктопная качалка,
Tauri, там уже решён резолв Kodik).

---

## 1. Рамки

- **Kotlin, нативно.** Не WebView-обёртка, не Tauri, не React Native.
- **Compose for TV** для UI, **Media3/ExoPlayer** для воспроизведения.
- Управление — только пульт (D-pad). Тач не предполагается.
- Обновление — свой апдейтер с GitHub Releases. Стора не будет.
- Целевое железо — дешёвый Android TV бокс, 1.5–2 ГБ RAM. Он же — эталон для замеров.

Из [anion](../anion) не переносится **ни строки кода**: `services/`, `store/`,
логика закладок и просмотренных серий пишутся заново на Kotlin. Это осознанная
цена нативного пути, а не недосмотр.

---

## 2. Ключевое решение: резолв по HTTP, а не через вебвью

anion-dl добывает HLS-манифест, поднимая скрытое окно вебвью и подслушивая его
сетевые запросы ([resolver.rs](../anion-dl/src-tauri/src/resolver.rs), 416 строк).
На Android этот путь тоже реализуем (`WebViewClient.shouldInterceptRequest`), но
он не нужен: у Kodik есть HTTP-эндпоинт, отдающий ссылки напрямую.

Схема из [kodikwrapper/video-links.ts](https://github.com/thedvxch/kodikwrapper/blob/master/src/video-links.ts):

1. Регексп по iframe-URL → `host`, `type`, `id`, `hash`, `quality`.
2. `GET https://{host}/ftor?type=..&id=..&hash=..` → JSON с `links` по качествам.
3. `src` каждой ссылки: сдвиг латинских букв на +18 → `atob()` → готовый m3u8.

Бонусом со страницы плеера снимаются `translationTitle` и `parseSkipButtons`
(тайминги опенинга/эндинга) — последнее нам не нужно, `skips` уже отдаёт
[anion-go](../anion-go) в `videos[].skips`.

### Поправка к разбору — снята, разбор был прав

Здесь стояла поправка: якобы `getLinks` в kodikwrapper шлёт ровно три параметра,
значит быстрый путь — один GET, а подписи нужны только для `extended`.
**Проверено живьём 12.08.2026 — неверно.** `GET /ftor?type=..&id=..&hash=..`
отдаёт 404, без подписей эндпоинт отвечает 500 с `Error code: rs`.

Рабочая схема уже была решена и покрыта тестами в
[anion-dl/src-tauri/src/kodik.rs](../anion-dl/src-tauri/src/kodik.rs) — оттуда она
и перенесена в `core-resolve`, вместо повторного реверса:

1. **GET страницы плеера** с `Referer: https://anion.online/` — Kodik подписывает
   параметры под домен-владелец вставки. В разметке лежат `type`/`id`/`hash` серии
   и подписи. Приоритет у `vInfo.*` над одноимёнными `var`: у страницы сезона в
   адресе `season`, а серия внутри уже `seria` со своим id и хэшем.
2. **POST на эндпоинт** формой из 11 полей (`d`, `d_sign`, `pd`, `pd_sign`, `ref`,
   `ref_sign`, `type`, `id`, `hash`, `bad_user`, `cdn_is_working`), с заголовками
   `Referer` = URL страницы плеера, `Origin` и `X-Requested-With`.
3. **Расшифровка `src`**: сдвиг латиницы (18 первым, остальные перебором) + base64.
4. **Качество из имени файла, а не из ключа ответа**: у `links["720"]` наблюдался
   URL с `480` внутри. Добор до желаемого — подменой числа в URL с проверкой
   `#EXTM3U`.

Медленный путь (парс `app.player_single.*.js` ради нового адреса эндпоинта)
остаётся, но включается только когда известный адрес отказал.

**Результат Э0:** пробник отдаёт живой `manifest.m3u8` (HTTP 200, `#EXTM3U`),
запрос 1080p корректно спускается до 720p. Вебвью-фолбэк первой версии не нужен.

### Что из разбора принимается без правок

- **Сдвиг не хардкодить в +18.** Перебирать сдвиги, принимать тот, что даёт
  валидный base64 с `.m3u8` внутри. Десять строк против «пустого манифеста» потом.
- **Лестницу качества и проверку `#EXTM3U` оставить.** `ftor` перечисляет качества,
  но 404 на 1080p при живых 720/480 — свойство CDN, а не плеера
  ([`is_playlist`](../anion-dl/src-tauri/src/resolver.rs)). `Referer: https://kodikplayer.com/`
  остаётся обязательным и для манифеста, и для сегментов.
- **Хрупкость переезжает, а не исчезает.** Ломаться будет формат ответа `ftor` или
  регексп по `urlParams` вместо разметки плеера. Выигрыш в том, что HTTP-путь
  падает за секунду с внятной ошибкой, а вебвью — за 60 секунд с дампом фреймов.
- **Посылка «реверсить бессмысленно» была ошибочной.** ROT18 + base64 держится
  годами; меняется эндпоинт (`/ftor` → `/kor` → …), а не шифр. Из неверной посылки
  вырос весь вебвью-тракт. Поэтому здесь фиксируем: **сначала пробуем HTTP,
  вебвью — только если HTTP доказанно не работает.**

## 3. Источники

Интерфейс `AnimeSource` с несколькими реализациями. Порядок — по тому, насколько
дёшево получить поток.

### AniLibria (AniLiberty) — первый

Публичный API без ключа, проверен живьём:

```bash
curl -s https://anilibria.top/api/v1/anime/releases/grand-blue-season-3
```

В каждом эпизоде сразу лежат `hls_480` / `hls_720` / `hls_1080`, `duration`,
превью кадра и `opening: {start, stop}` / `ending: {start, stop}`. Резолва нет
вообще — ExoPlayer получает URL и играет. Отдельно `torrents[]` с `magnet`,
сидами, кодеком и качеством.

Ограничения: только их собственная озвучка, каталог у́же Kodik, есть
`is_blocked_by_geo` / `is_blocked_by_copyrights`, а в URL манифеста видно
`isWithVideoAds=1` — для неавторизованных в поток вшита реклама. Проверить, снимает
ли это авторизация.

### Kodik через anion-go — второй

Каталог, поиск, детали и `videos[].iframeUrl` берутся из [anion-go](../anion-go)
через прокси на Vercel: `/proxy/api/anime/feed`, `/proxy/api/anime/:id`,
`POST /proxy/api/anime/search`. Дальше iframe-URL резолвится в m3u8 по схеме
из §2. Даёт широкий каталог и выбор озвучки — у проверенного тайтла 35 озвучек
против одной у AniLibria.

Одна запись в `videos` — это «серия N в озвучке X»: все озвучки лежат вперемешку
одним списком, поэтому выбор озвучки собирается группировкой по `data.dubbing`.

Заодно бесплатно приходит синхронизация с вебом: закладки и авторизация там уже
есть, и просмотренное на телевизоре совпадёт с сайтом.

### Прочее — потом или никогда

- **Aniboom / Animego, JutSu, Anime365** — парсеры описаны в
  [AnimeParsers](https://github.com/YaNesyTortiK/AnimeParsers), логика переносима.
  Каждый — отдельная реализация `AnimeSource`, каждый так же хрупок. Только если
  двух основных не хватит.
- **Торренты.** Технически: `libtorrent4j` + локальный HTTP-сервер под ExoPlayer.
  Но перемотка вперёд ждёт куски, на старых тайтлах сидов нет, сезон — 9 ГБ на
  диск бокса. Разумно как фоновая **загрузка** (сценарий anion-dl на ТВ), а не как
  стриминг. Не в первой версии.

## 4. Архитектура

```
app/            Compose for TV, экраны, навигация, фокус
core-source/    AnimeSource + реализации (AniLibria, Kodik/anion-go)
core-resolve/   KodikResolver: iframe URL → m3u8 + Referer
core-player/    обвязка Media3: скипы, восстановление позиции, переролв по 403
core-data/      Room (просмотренное, кэш каталога), синк с anion-go
```

`core-resolve` не зависит от Android — чистый Kotlin на OkHttp, гоняется в
JVM-тестах и в CLI-пробнике. Прямое следствие разбора: сейчас в anion-dl
`attempt_resolve` требует `AppHandle` и юнит-тестами покрыт только `split_quality`.

Резолв прячется за интерфейс с двумя реализациями:

- `LocalKodikResolver` — HTTP прямо в приложении, дефолт;
- `RemoteResolver` — дёргает эндпоинт в anion-go, если тот появится (см. §7).

## 5. Этапы

Каждый этап заканчивается проверяемым результатом. Порядок такой, что риск
проверяется раньше, чем в него вкладывается работа.

**Э0. Пробник резолвера. — СДЕЛАНО (12.08.2026).**
JVM-модуль без Android и UI: на вход живой iframe-URL, на выход играющий m3u8.
*Проверяет:* берёт ли `/ftor` голые `type/id/hash` (§2), жив ли дефолтный
эндпоинт, нужен ли `Referer`, какие качества реально отдаются.
*Результат:* `/ftor` голых параметров не берёт (404) — схема перенесена из
anion-dl, см. §2. Пробник отдаёт живой манифест (HTTP 200, `#EXTM3U`), запрос
1080p спускается до 720p. Вебвью-фолбэк в первой версии не нужен.

**Э1. Слой источников. — СДЕЛАНО (12.08.2026).**
`AnimeSource`, AniLibria целиком (каталог, поиск, эпизоды, HLS) и клиент anion-go
для каталога Kodik.
*Результат:* 12 тестов на фикстурах (реальные ответы API, сеть не трогается) плюс
живая проверка пробником: AniLibria — 6 серий и играющий 720p; Kodik — 35 озвучек,
11 серий выбранной и играющий 720p через резолвер.

**Э2. Kodik-резолвер боевой. — СДЕЛАНО (12.08.2026).** Код обоих путей и тесты
на MockWebServer: быстрый `/ftor`, медленный через `app.player_single.*.js`,
кэш найденного адреса, `EndpointNotFound`, `Error code: rs` в тексте ошибки.

**Э3. Плеер. — код готов, не проверено на боксе.** Обвязка Media3 в `core-player`;
UI плеера — уже Э4, здесь только воспроизведение и управление.

*Состав:*
- `StreamDataSourceFactory` — `OkHttpDataSource.Factory` с заголовками из
  `ResolvedStream`. `Referer` обязан уходить и на манифест, и на каждый сегмент.
- `ExoPlaybackController` — подготовка, play/pause, `seekBy(±10 с)`, `StateFlow`
  состояния. Без `PlayerView` из Media3: его фокус-модель на пульте ведёт себя
  непредсказуемо.
- `RemoteKeyMap` — раскладка пульта отдельным файлом: у боксов кнопки
  разъезжаются, и это первое, что придётся править под конкретное железо.
- `SkipController` — кнопка «пропустить» по `Skips`. У AniLibria отрезок полный,
  у Kodik известно только начало и берётся окно `Segment.DEFAULT_WINDOW_SECONDS`.
- `ReResolveOnForbidden` — 403 на сегменте означает протухшую подпись
  (у Kodik срок виден прямо в URL: `…:2026081307`). Нужен один тихий переролв с
  продолжением с той же секунды, **не шторм повторов**; второй 403 подряд —
  ошибка пользователю. Плюс упреждающий переролв по `SignatureClock`.
- Позиция отдаётся в `PlaybackProgressListener`; запись в Room — Э5. При
  `preferredQuality` недоступного качества — спуск по лестнице, а не отказ.

*Готово, когда:* серия смотрится с пульта от начала до конца, без клавиатуры и
мыши, и переживает протухание подписи на длинной серии. Юнит-тесты скипов и
перерола зелёные; прогон на боксе — когда появится ТВ-образ или железо.

**Э4. UI. — код готов, не проверено на боксе.** Compose for TV.

*Состав:*
- Главная: подборки по источникам. Ряд «продолжить смотреть» появится в Э5 —
  пока данных нет, пустой ряд не рисуем. На ТВ ряды важнее поиска.
- Каталог: `LazyVerticalGrid`, пагинация, фильтр по источнику. Постеры грузятся
  в размер плитки (`thumbnailUrl`), а не оригинал — на боксе 1.5 ГБ это решающе.
- Поиск: история запросов (SharedPreferences до Room) и голосовой ввод
  (`RecognizerIntent`) впереди строки; экранная клавиатура — последний вариант.
- Карточка тайтла: описание, выбор озвучки списком с фокусом, список серий.
  Отметка просмотренных — Э5.
- Фокус: `focusRestorer`/`focusRequester`. Куда уходит D-pad с края ряда и что
  фокусируется при возврате назад — половина работы над ТВ-UI.
- Overscan: 5% полей по краям, часть телевизоров режет картинку. Плеер — на весь
  экран, панель Compose, не `PlayerView`.

*Готово, когда:* на боксе прокрутка каталога не проседает ниже 30 fps.

**Э5. Состояние. — код готов, живой sync требует проверки с аккаунтом.** Room как источник правды при офлайне, anion-go догоняется при
сети.

*Состав:*
- Сущности: прогресс серии, закладки, кэш каталога, история поиска. Схемы
  экспортируются в `core-data/schemas` и коммитятся — миграции проверяются диффом.
- Прогресс пишется часто (плеер тикает), на сервер уезжает редко — очередь с
  дебаунсом, по смыслу как `bookmarkProgressQueue` в вебе, но кодом заново.
- Конфликт разрешается по `updatedAt`; локальное несинхронизированное никогда не
  затирается серверным.
- Досмотром считать ~90% длительности, а не последнюю секунду.

*Готово, когда:* серия, досмотренная на телевизоре, отмечена на сайте.

Реализовано: схема Room v1 экспортирована в `core-data/schemas`; прогресс,
закладки, кэш каталога и история поиска подключены к UI. Плеер восстанавливает
позицию, пишет её с debounce 2 с и считает серию досмотренной на 90%. Сетевой
sync отделён debounce 12 с, использует существующую сессию anion-go и CAS по
локальному `updatedAt`, поэтому новый тик не подтверждается старым ответом.

В модели закладки anion-go нет `updatedAt`. Поэтому pull заменяет только чистую
локальную запись, а `dirty` никогда не трогает; успешный PUT/POST считается
подтверждением. Сервер знает только Yumi/Kodik ID — AniLibria синхронизируется
локально, но не отправляется на сайт. Инструментальная схема собирается, живой
критерий «телевизор → сайт» остаётся прогнать с реальным аккаунтом и боксом.

**Э6. Дистрибуция.**

*Состав:*
- [x] Подпись релиза своим ключом из `keystore.properties` (в git не коммитится)
  или секретов GitHub Actions. Теги `vMAJOR.MINOR.PATCH` собирают APK/AAB,
  проверяют подпись, считают SHA-256 и создают GitHub Release.
  Апдейтер требует, чтобы новая версия была подписана тем же ключом, что и старая.
- Настоящие иконка и баннер 320×180 вместо нынешних заглушек.
- Апдейтер: проверка релиза на GitHub, скачивание, установка через
  `PackageInstaller` и `REQUEST_INSTALL_PACKAGES`, `FileProvider` под APK.
  Версии сравнивать семантически, пререлизы игнорировать.

*Готово, когда:* обновление ставится с самого телевизора, без ноутбука и adb.

**Э7. Необязательное.** Префетч следующей серии, торренты как загрузчик,
перенос резолва в anion-go (§7).

## 6. Подводные камни

Отсортированы по тому, насколько поздно вылезут.

- ~~**Vercel-защита на `anion.online/api`.**~~ **Снято, вопрос был в адресе.**
  `/api/*` на Vercel — каталог serverless-функций (там SSR), туда ходить не надо.
  Прокси к anion-go живёт на **`/proxy/api`** ([anion/middleware.js](../anion/middleware.js)),
  а обход WAF — заголовок **`X-Anion-Client`** со значением клиента
  ([anion-dl/src/app/api/api.config.ts](../anion-dl/src/app/api/api.config.ts)).
  Middleware пробрасывает дальше `cookie`, `authorization` и всё на `x-`.
  Проверено: `/proxy/api/anime/feed` с заголовком — 200, без него — 429.
  anion-tv ходит с тем же значением `anion-dl`: правило под него уже заведено,
  а отдельная метка ничего не защищает — заголовок подделывается тривиально.
- **Подпись в URL манифеста живёт ограниченное время.** Ломается не старт, а
  середина длинной серии. Отсюда переролв в Э3, а не «потом».
- **Задержка старта.** Даже HTTP-резолв — это лишний round-trip перед первым
  кадром. На боксе с плохим Wi-Fi заметно. Префетч следующей серии во время
  просмотра (Э7) снимает это в сценарии «смотрю сезон подряд».
- **Экранная клавиатура на пульте.** Поиск текстом на ТВ мучителен. История
  запросов, разделы и «продолжить смотреть» важнее, чем строка поиска.
- **Память.** Compose + Media3 + кэш постеров на 1.5 ГБ. Постеры грузить в
  размер плитки, а не оригинал (у AniLibria есть `thumbnail` и `optimized.webp`).
- **Обновляемость.** Сломался резолвер — все установки мертвы до тех пор, пока
  пользователь сам не поставит новый APK. Это главный аргумент за §7.
- **Правовая сторона.** Всё это — неофициальный разбор чужих плееров, и вырезание
  плеера Kodik вырезает и его рекламу. Для личной установки на свой телевизор
  вопрос практический, но в стор такое не пойдёт — что заранее принято в рамках.

## 7. Открытый вопрос: резолв в anion-go

anion-go — **свой** сервис, в отличие от `api.yani.tv`. Значит резолв можно
поднять там: эндпоинт вида `GET /api/anime/:id/stream?videoId=..&quality=..`,
внутри та же схема из §2 на Go.

Что это даёт: Kodik сломался — чинится на сервере, все клиенты живы, APK обновлять
не надо; резолв кэшируется централизованно, задержка старта исчезает; anion-dl
теряет 416 строк Rust и скрытое окно; веб-версия получает прямой поток и
перестаёт зависеть от iframe.

Что мешает: сервер начинает нести резолв заметно явнее клиента.

Решение отложено, но `core-resolve` под него уже готов — `RemoteResolver` меняется
на `LocalKodikResolver` одной строкой в DI.

## 8. Что сделать первым

1. Э0 — пробник, один живой iframe-URL, ответ на вопрос про `/ftor`.
